# AI4SEC 技术学习路线

## 学习目标

AI4SEC 指使用人工智能和机器学习解决网络安全问题。本路线围绕四类任务展开：

1. **威胁检测**：识别异常流量、恶意域名、恶意软件和可疑行为。
2. **安全运营**：分析告警、关联证据、辅助事件研判。
3. **漏洞检测**：利用代码模型或大语言模型发现和分析代码中的潜在漏洞。
4. **威胁情报**：从安全报告中提取指标、攻击行为和关联关系。

学习时始终围绕“安全任务 → 数据 → 模型 → 评估 → 实际使用”组织知识。先完成一条贯通路线，再按兴趣深入其他场景。

## 一、理解 AI4SEC 的任务

- [ ] 区分安全规则检测、基于已知标签的分类、异常检测和大语言模型辅助分析。
- [ ] 理解一次检测的完整链路：采集安全数据、提取特征、模型判断、生成告警、人工验证、反馈改进。
- [ ] 认识常见输入：网络流量记录、DNS 查询、主机行为日志、可执行文件特征、源代码、漏洞报告。
- [ ] 理解常见输出：恶意概率、异常分数、威胁类别、疑似漏洞位置、告警原因和证据。
- [ ] 理解误报、漏报、分析成本和响应时效对安全工作的影响。

**完成标准**：能用自己的话说明一个 AI 安全检测系统的输入、输出和使用场景。

## 二、处理安全数据

### 2.1 认识安全数据

- [ ] 流量数据：协议、连接持续时间、上下行字节数、包数和连接频率。
- [ ] DNS 数据：域名、查询频率、域名字符分布、解析结果和时间变化。
- [ ] 主机数据：进程、父子进程关系、命令行、文件操作和网络连接。
- [ ] 代码数据：函数、调用关系、数据流、漏洞修复前后的代码。
- [ ] 威胁情报：IP、域名、文件哈希、漏洞编号、攻击行为和报告上下文。

### 2.2 构建训练数据

- [ ] 根据检测目标明确样本单位：一条流量、一段时间窗口、一个进程、一段代码或一条告警。
- [ ] 区分正常、恶意和未知样本，记录标签来源与标注时间。
- [ ] 清理缺失值、重复样本和异常格式；保留必要的来源信息以便追溯。
- [ ] 提取与任务有关的统计、文本、时序或结构特征，并确认预测时能够取得这些特征。
- [ ] 处理类别不平衡：观察正负样本比例，尝试类别权重、采样和阈值调整。
- [ ] 按时间、主机、攻击活动或代码项目等适合任务的维度切分数据，避免高度相似的样本跨集合。
- [ ] 特征转换的参数和重采样只在训练集上拟合或执行；用验证集调参和选择模型，用独立测试集评估。
- [ ] 排查标签泄漏：不能把攻击类型、事后处置结果或其他预测时未知的信息当作输入。

**完成标准**：能把一份安全数据转换成可训练的数据集，并解释标签、特征和切分方式。

## 三、建立安全检测模型

### 3.1 有监督检测

- [ ] 用逻辑回归或随机森林建立恶意流量、恶意域名或恶意样本分类基线。
- [ ] 理解决策树、随机森林和梯度提升树如何利用安全特征。
- [ ] 比较模型与简单规则的结果，找出各自捕获和遗漏的样本。
- [ ] 分析特征重要性，并回查原始证据，确认模型没有依赖偶然的环境特征。

### 3.2 异常检测

- [ ] 理解异常检测适合标签少、需要发现偏离常态行为的场景。
- [ ] 使用 Isolation Forest 等方法生成异常分数，并在有标签的验证数据上选择阈值。
- [ ] 分析异常与攻击的区别：新业务、扫描器或配置变更也可能表现为异常。
- [ ] 对比异常检测与已知攻击分类在发现能力和误报量上的差异。

### 3.3 安全时序与关联

- [ ] 将连续登录、进程启动或网络连接整理为按时间排列的行为序列。
- [ ] 理解时间窗口、事件顺序、行为频率和关联上下文对检测的价值。
- [ ] 将多个事件关联为一次安全事件，避免只凭单条日志下结论。
- [ ] 根据具体任务再学习序列模型、图模型等方法，并与简单统计基线比较。

**完成标准**：能训练一个检测模型，解释它使用了哪些安全数据，以及为什么选择这个方法。

## 四、评估模型是否对安全工作有用

- [ ] 使用混淆矩阵理解真正例、假正例、真负例和假负例。
- [ ] 理解精确率、召回率、F1、误报率和漏报率在安全场景中的含义。
- [ ] 在攻击样本稀少时，结合精确率—召回率曲线、平均精确率和实际告警数量分析结果。
- [ ] 根据分析人员每天能处理的告警量，在验证集选择阈值，并在测试集报告最终结果。
- [ ] 分攻击类型、时间段、主机或项目检查效果，识别整体指标掩盖的问题。
- [ ] 对误报和漏报做案例分析，说明问题来自数据、特征、标签还是模型。
- [ ] 检查时间变化和环境变化带来的效果下降，建立人工反馈和复评流程。

**完成标准**：能回答“模型每天产生多少告警、其中有多少值得处理、会漏掉哪些攻击”。

## 五、用大语言模型辅助安全分析

### 5.1 告警研判

- [ ] 将告警、相关日志、资产信息和已有情报整理成适合分析的上下文。
- [ ] 让模型输出事件摘要、可疑证据、待验证问题和建议的下一步。
- [ ] 让输出明确引用输入中的日志或情报，区分已知事实与推断。
- [ ] 对比人工研判结果，评估结论是否正确、证据是否充分以及节省了多少时间。
- [ ] 将自动分析结果交由人工复核，再执行封禁等处置动作。

### 5.2 安全知识检索

- [ ] 围绕漏洞说明、安全规则和历史事件构建可检索的资料库。
- [ ] 理解关键词检索、向量检索和混合检索在安全术语、漏洞编号查询中的适用性。
- [ ] 将检索到的内容连同来源交给模型，生成带证据的安全问答。
- [ ] 用一组安全问题评估检索命中、答案正确性、引用准确性和无证据时的表现。

### 5.3 安全工具协作

- [ ] 设计“提出分析任务 → 读取证据 → 调用安全工具 → 汇总结果 → 人工确认”的工作流。
- [ ] 让模型只调用与当前任务有关的工具，并记录工具输入、输出与分析依据。
- [ ] 对漏洞发现、攻击面分析等任务，在授权范围内使用隔离环境验证结果。

**完成标准**：能做出一个有证据来源、可供人工复核的安全分析助手。

## 六、AI4SEC 专项方向

完成前面的共同流程后，从以下方向选择一个作为主要深入方向。

### 方向 A：恶意流量与异常行为检测

- **任务**：检测扫描、暴力尝试、异常通信等可疑行为。
- **数据**：网络流、DNS、登录日志或主机事件。
- **方法**：流量特征工程、分类、异常检测、时间窗口和事件关联。
- **重点问题**：数据泄漏、攻击样本稀少、环境变化、误报量。
- **练习**：用 [CIC-IDS2017](https://www.unb.ca/cic/datasets/ids-2017.html) 的流量特征建立分类基线，再分析按时间或攻击场景划分时的效果。数据集按日期安排攻击活动，要特别检查时间、地址等字段形成的捷径。

### 方向 B：AI 辅助代码漏洞检测

- **任务**：判断代码是否存在漏洞，定位可疑位置并解释触发条件。
- **数据**：源代码函数、漏洞修复前后代码、漏洞类型和项目上下文。
- **方法**：代码文本特征、代码表示、代码语言模型、大语言模型辅助审计。
- **重点问题**：跨函数上下文不足、漏洞标签噪声、相似代码泄漏、可疑结果验证。
- **练习**：使用 [CodeXGLUE Defect Detection](https://github.com/microsoft/CodeXGLUE/blob/main/Code-Code/Defect-detection/README.md) 对代码函数做二分类；再抽查误报与漏报，比较规则、传统模型和代码模型。

### 方向 C：恶意软件检测

- **任务**：判断文件是否恶意，或识别已知恶意软件类别。
- **数据**：文件结构、导入函数、字节统计、字符串或沙箱行为。
- **方法**：静态特征分类、行为特征分类、样本家族与时间维度分析。
- **重点问题**：样本版本变化、相似家族泄漏、已知样本与新样本的效果差异。
- **练习**：使用 [EMBER](https://github.com/elastic/ember) 提供的恶意软件特征和基线流程，比较不同分类器并分析错误样本。

### 方向 D：AI 安全运营与威胁情报

- **任务**：对安全告警做排序和解释，从报告中提取威胁指标与攻击行为。
- **数据**：告警、日志、资产信息、历史处置记录和公开威胁报告。
- **方法**：分类、检索增强生成、实体提取、事件关联和结构化输出。
- **重点问题**：证据是否可追溯、提取是否准确、告警优先级是否符合实际处置需求。
- **练习**：构建一个告警研判助手，输入一条告警及其上下文，输出事件摘要、证据、风险判断和待确认事项。

## 七、推荐学习顺序

| 阶段 | 重点 | 阶段成果 |
| --- | --- | --- |
| 1 | AI4SEC 任务和安全数据 | 说清输入、标签、输出和评估方式 |
| 2 | 安全数据清洗、特征和切分 | 产出可复现的训练、验证、测试数据 |
| 3 | 分类与异常检测 | 完成规则基线和至少一个模型基线 |
| 4 | 安全场景评估与错误分析 | 给出指标、告警量、误报和漏报案例 |
| 5 | 大模型辅助安全分析 | 完成一个可引用证据的安全分析流程 |
| 6 | 选择一个专项深入 | 完成项目、实验记录和项目说明 |

推荐第一个项目选择**恶意流量检测**或**告警研判助手**：前者适合练习安全数据和机器学习，后者适合练习大模型与安全工作流。

## 九、AI4SEC 起步问答

### 任务与数据

1. **问：AI4SEC 中的分类和异常检测有什么区别？**<br>
   答：分类利用已标注样本学习已知类别；异常检测寻找偏离常态的样本，结果需要结合上下文判断是否构成攻击。

2. **问：做恶意流量检测时，一条样本可以是什么？**<br>
   答：可以是一条网络流，也可以是某个主机在固定时间窗口内的流量统计；选择取决于要识别的行为。

3. **问：安全检测中的标签泄漏是什么？**<br>
   答：训练或评估使用了预测时不应获得的标签信息或事后信息，使模型效果被高估。

4. **问：为什么安全数据需要考虑时间切分？**<br>
   答：实际系统通常用过去的数据预测未来；时间切分有助于检查模型面对后续数据时的表现。

5. **问：为什么相似样本不能随意分到训练集和测试集？**<br>
   答：模型可能记住重复流量、同一攻击活动或相似代码，使测试结果不能反映对新样本的效果。

### 模型与评估

6. **问：为什么安全检测不能只看准确率？**<br>
   答：正常样本远多于攻击样本时，全部预测为正常也可能得到很高的准确率，却无法发现攻击。

7. **问：安全告警的精确率是什么？**<br>
   答：模型报出的告警中，真正属于目标威胁的比例。

8. **问：安全检测的召回率是什么？**<br>
   答：所有真实目标威胁中，被模型检测出来的比例。

9. **问：提高检测阈值通常会带来什么变化？**<br>
   答：通常会减少告警量，并改变误报和漏报；具体变化应在验证数据上测量。

10. **问：异常流量一定是恶意流量吗？**<br>
    答：不一定。新业务、配置变化和正常的集中访问也可能偏离历史行为。

11. **问：为什么要把机器学习检测与规则基线比较？**<br>
    答：可以判断模型是否真正补充了现有规则，并比较双方的漏报、误报和维护成本。

12. **问：安全检测中的模型漂移指什么？**<br>
    答：业务环境、用户行为或攻击方式变化后，模型输入或预测效果发生变化，需要持续监测和复评。

### 安全场景

13. **问：如何用 AI 辅助安全告警研判？**<br>
    答：汇集告警、日志、资产和情报，让模型提取证据、生成判断与待验证事项，再交给分析人员复核。

14. **问：AI 研判结果为什么需要列出证据？**<br>
    答：分析人员需要回查日志或情报，核对结论是否得到支持，并据此决定后续处置。

15. **问：代码漏洞检测的模型通常以什么为输入？**<br>
    答：可以输入函数代码、相关调用上下文、代码结构或数据流；具体范围由检测任务和模型决定。

16. **问：为什么函数级漏洞检测需要关注上下文？**<br>
    答：漏洞触发条件可能涉及调用者、跨函数数据流或外部配置，只看单个函数可能缺少判断依据。

17. **问：如何评估大模型生成的漏洞分析？**<br>
    答：检查漏洞类型、位置、触发条件和证据，并用可复现的测试或人工审计确认。

18. **问：为什么恶意软件检测要关注样本时间和家族？**<br>
    答：同家族或相近时间的样本可能高度相似，按时间和家族分析更有助于了解面对新样本的效果。

19. **问：威胁情报提取可以从报告中识别哪些对象？**<br>
    答：可以提取域名、IP、文件哈希、漏洞编号和攻击行为，并保留对应的原文证据。

20. **问：安全知识库问答如何检查答案可靠性？**<br>
    答：分别检查资料是否被正确检索、答案是否与资料一致、引用是否支持结论，以及资料不足时是否明确说明。
